# Сайт Воскресной компьютерной школы

## Быстрый запуск на localhost

Откройте PowerShell и выполните:

```powershell
cd D:\sunschool-site
npm run dev
```

Затем откройте в браузере **http://localhost:4321/**. Если запускаете проект впервые, перед `npm run dev` один раз выполните `npm ci`.

Исходный код сайта Воскресной компьютерной школы мехмата ЮФУ. Публичный адрес — [sunschool.mmcs.sfedu.ru](https://sunschool.mmcs.sfedu.ru). Репозиторий хранит исходники; готовый сайт размещается на сервере мехмата, **не на GitHub Pages**.

Сайт собран на [Astro 7](https://astro.build/) в режиме статической генерации. Основные страницы написаны в Markdown, страница преподавателей — в Astro. Серверный JavaScript, PHP и база данных для работы этих страниц не требуются.

## Что установить на компьютер разработчика

1. [Node.js](https://nodejs.org/en/download) **22.12.0 или новее** из поддерживаемой чётной ветки. Вместе с Node.js устанавливается npm. Требование к версии задаёт установленный в проекте Astro.
2. [Git](https://git-scm.com/install/windows) — чтобы клонировать репозиторий и отправлять изменения.
3. Редактор кода, например [Visual Studio Code](https://code.visualstudio.com/) с [официальным расширением Astro](https://marketplace.visualstudio.com/items?itemName=astro-build.astro-vscode). Редактор можно выбрать другой.

На Windows команды ниже можно запускать в PowerShell. Проверка после установки:

```powershell
node --version
npm --version
git --version
```

Astro, TypeScript и остальные зависимости **не нужно устанавливать глобально**: `npm ci` установит их в проект из `package-lock.json`. PHP, Ruby и MySQL для разработки этого статического сайта не требуются. Файлы страниц сохранены в UTF-8.

## Локальный запуск

```powershell
git clone https://github.com/sunschoolmmcs/sunschool-site.git
cd sunschool-site
npm ci
npm run dev
```

Если проект уже находится на компьютере, начните с перехода в его папку и `npm ci`; повторно клонировать его не нужно. После запуска откройте адрес, который выведет Astro (обычно `http://localhost:4321/`). Сервер разработки работает, пока открыто окно PowerShell; остановить его можно сочетанием `Ctrl+C`. Изменения в страницах и стилях обычно отображаются после обновления браузера.

## Проверка и сборка

```powershell
npm run check
npm run build
npm run preview
```

`check` проверяет страницы Astro и типы; `build` создаёт готовые статические файлы в `dist/`; `preview` позволяет посмотреть собранный сайт локально. Для повторяемой установки зависимостей используйте `npm ci` и храните `package-lock.json` в репозитории.

На рабочем сервере нужно раздавать содержимое `dist/` как статические файлы. Конфигурация Astro создаёт внутренние страницы как `dist/имя-страницы/index.html`, при этом публичные адреса задуманы без `.html` и завершающего `/` (например, `/courses`). Веб-серверу потребуется внутреннее правило маршрутизации таких адресов к соответствующим `index.html`; настройку следует проверить на сервере мехмата перед переключением домена.

## Перенос на сервер мехмата

Автоматическая публикация из GitHub пока не настроена. Для ручного переноса:

1. На локальном компьютере выполните `npm ci`, `npm run check`, `npm run build`, затем при необходимости `npm run preview` для проверки собранной версии.
2. У администратора сервера уточните каталог, из которого раздаётся сайт, и способ доступа (например, SFTP/SSH). Сначала загрузите сайт в **отдельный тестовый каталог**, не поверх действующего сайта.
3. В тестовый каталог скопируйте **содержимое `dist/`**, а не исходники `src/`, `node_modules/` или папку проекта целиком. `index.html` из `dist/` должен оказаться в корне тестового сайта. Node.js на веб-сервере для раздачи этой сборки не нужен.
4. Отдельно обеспечьте доступность фотографий преподавателей по `/images/teachers/...` и старых галерей по `/PhotoGalleries/...`: часть этих файлов не хранится в GitHub. Не удаляйте существующие серверные каталоги с фотографиями или ученическими работами при обновлении.
5. Проверьте на тестовом адресе главную страницу, внутренние адреса без завершающего `/`, фотографии, ссылки и мобильный вид. После этого согласуйте резервную копию старого сайта и переключение рабочего каталога с администратором.

Точный путь на сервере и правила маршрутизации в этом репозитории не заданы — их нельзя подставлять в команды копирования наугад. Команды, которые очищают целевой каталог или синхронизируют его с удалением лишних файлов, могут уничтожить не входящие в репозиторий фото и другие материалы.

## Где что находится

| Путь | Назначение |
| --- | --- |
| `src/pages/` | Страницы сайта и тексты курсов (`.md`), страница преподавателей (`teachers.astro`). |
| `src/layouts/BaseLayout.astro` | Общий HTML-каркас страниц. |
| `src/components/` | Шапка, меню и футер. |
| `src/data/navigation.ts` | Пункты верхнего меню. |
| `src/styles/global.css` | Общие стили и адаптивное оформление. |
| `public/` | Статические файлы, которые Astro копирует в `dist/` без преобразования. |
| `astro.config.mjs` | Домен сайта и параметры статической сборки. |

Для новой страницы добавьте файл в `src/pages/` с frontmatter `layout`, `title`, `description`; для пункта меню обновите `src/data/navigation.ts`. Внутренние ссылки пишите от корня сайта: `/courses`, `/images/имя-файла.jpg`.

## Файлы, которых нет в GitHub

Следующие каталоги исключены через `.gitignore`:

- `public/images/teachers/` — фотографии преподавателей. Страница `/teachers` ссылается на них по адресам `/images/teachers/...`. При сборке из чистого клона добавьте каталог отдельно **до** `npm run build` либо поместите фотографии в `dist/images/teachers/` после сборки. При обновлении сайта не удаляйте эти файлы с сервера.
- `public/works/` — архив старых ученических работ; нынешние страницы сайта его не используют.
- `legacy-portfolio/` — старые серверные PHP/Ruby-скрипты. Они содержат конфиденциальные настройки и не должны попадать ни в репозиторий, ни в статическую сборку.

Страница `/portfolio` сейчас является заглушкой и убрана из верхнего меню. Старое динамическое портфолио зависело от PHP, Ruby, MySQL и отдельного каталога работ на сервере; оно **не переносится** этой статической сборкой.

На странице фотогалереи часть превью и ссылок указывает на старый адрес `sunschool.mmcs.sfedu.ru/PhotoGalleries/...`. Перед заменой старого сайта новым нужно сохранить соответствующие каталоги `PhotoGalleries` по тем же URL, иначе эти фотографии и альбомы перестанут открываться.

Перед отправкой изменений в публичный репозиторий проверяйте состав коммита и не добавляйте пароли, базы данных или личные файлы учеников.
